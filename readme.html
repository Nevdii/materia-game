Readme

A Twitch chat bot for the "Twitch Chat Game" project: viewers earn XP just by watching the stream, spend it gambling for Final Fantasy VII materia, and can check their collection (or anyone else's) with chat commands.

How it works

  • Every minute (XP_TICK_MINUTES) that the channel is actually live, the bot asks Twitch who is currently sitting in chat and gives each of them XP (XP_PER_TICK). No typing required — just being there counts as "watching". XP stops accruing the moment the stream goes offline (chat is joinable even when offline, so this is checked separately).
  • Viewers spend XP with !rollmateria <colour> to gamble for a random materia of that color - see the cost/odds table below. Materia is never handed out automatically; rolling is the only way to get any.
  • Materia come in four rollable colors (Magic/Green, Command/Yellow, Independent/Purple, Summon/Red - Support/Blue is retired for now, see below), each with its own signature "jackpot" materia and a documented set of odds - see below. The full catalog lives in src/materiaCatalog.js — edit it freely to add/remove materia or retune odds and costs, then run npm run print-odds to regenerate the table below.
  • Some materia can be merged into a stronger tier with !upgrade <materia> e.g. 5 Fire merges into 1 Fire2 - see "Upgrading materia" below for the full list of chains.
  • Everyone's XP and collection are stored in a local SQLite database (data/materia.db), so it survives restarts.
  • If the bot is running as your own account, your own typed commands still work — the bot only ignores messages that are its own replies echoing back, not everything from that login.
  • Everyone starts with a Buster Sword (2 materia slots) and an Iron Bangle (1 materia slot) — 3 slots total, same as Cloud's opening gear. !materia shows exactly what's equipped in each, your Equipped Materia Value, and everything you own but haven't slotted in yet - it's the one screen that covers what used to be several separate commands.
  • Beating certain bosses with !fight drops gear that automatically replaces what you have equipped and grows your total slot count (Iron Bangle → Titan Bangle → Carbon Bangle; Buster Sword → Mythril Saber) - see "Boss drops" below.

Chat commands

Kept deliberately short so it's not overwhelming for a new viewer. A few commands that used to exist on their own (!collection, !stats, !gear, !loadout, !bosses) have been folded into !materia or !materiagame info instead - see the note under the table.

CommandWhat it does
!xp [user]XP balance and a quick reference of what each color costs to roll
!rollmateria <colour>Spend XP to gamble for a random materia of that color (purple/yellow/green/red)
!materia [user]The full screen: XP, what's in each weapon/armor slot (with names), unassigned materia, Equipped Materia Value, and (at the very end) any pet you own, e.g. Pet: Baby Chocobo - Ultra Rare
!equip <materia>[, <materia>, ...]Equip one or more materia you own, filling the next open slot(s) in order
!unequip <slot|materia>Unequip by slot number or by materia name
!upgrade <materia>Merge 5 of a materia into its next tier (e.g. 5 Fire → 1 Fire2) - see "Upgrading materia" below
!salvage <materia>Break down one spare (unequipped) copy of a materia into XP: 1/3 of its XP value, rounded down - see "Salvaging materia" below
!fight <boss>Battle a boss using your equipped materia - needs an active unlock, see "Unlocking !fight" below
!battle <user>Coming soon! Will be a PvP challenge, gated by its own channel-point/bits unlock - see "Ideas for next iterations" below
!rankLeaderboard ranked by bosses defeated first, "Materia Power" (rarity-weighted) as the tiebreak
!materiagameReplies with just a link to the command-guide poster (GUIDE_IMAGE_URL in .env, defaulting to the hosted Imgur album). Set it blank and it lists the commands in chat instead
!materiagame infoLists every boss, its difficulty, and whether !fight is currently unlocked (this used to be the standalone !bosses command)

Retired commands and where their info went: !collection/!inventory (now shown inside !materia's unassigned list) and !gear (the equipped weapon/armor names already appear right in !materia) are gone entirely; !stats is gone (the !materia screen now ends with "Equipped Materia Value", not stat bonuses); !loadout was a narrower version of !materia with the XP/unassigned parts stripped out, so it's gone too - just use !materia; !bosses is now !materiagame info.

The command prefix (!) is configurable via COMMAND_PREFIX. Equipment slots are fixed by the equipment itself (see src/equipmentCatalog.js), not by an env setting.

Example: !materia

Nevdi — 42 XP | Buster Sword | 🟢 0 Fire | Iron Bangle | 0 | Unassigned Materia: 1 x Ice, 1 x Knights of the Round | Equipped Materia Value: 10

Twitch chat messages are single line (no real line breaks - a bare newline gets stripped or corrupts the message rather than actually starting a new line), so the whole screen - equipment, unassigned list, and the total value of what's equipped - is folded into one message, and | is used consistently everywhere a section break is needed: it separates the major sections (XP, equipment, unassigned, equipped value), splits each equipment group's name from its own gauge, and separates the equipment groups from each other too (an earlier version used a • bullet for that last job; it's | throughout now). Each equipment group is <name> | <gauge> <names>: the gauge is one token per slot it has (the Buster Sword always shows two tokens, no matter how many are filled), where a filled slot's 0 is replaced by a colored dot matching that materia's type (🟢 Magic, 🟡 Command, 🟣 Independent, 🔴 Summon), not just decorated with one, so the token count never grows past the slot count; an empty slot stays a plain 0. Whatever's actually equipped is then named right after the gauge, in slot order. So Buster Sword | 🟢 0 Fire above means slot 1 has a Magic-type materia (Fire) and slot 2 is empty, and Iron Bangle | 0 means its one slot is empty too. Equipped Materia Value: 10 is Fire's value (Common = 10) - the combined boss-fight value of whatever's currently equipped (see "Materia values"), the same total !fight uses. Spare materia sitting in the unassigned list don't count, so two Bolts equipped reads Equipped Materia Value: 20. Typing !equip Ice after the example above would fill the Buster Sword's second slot, turning the equipment section into Buster Sword | 🟢 🟢 Fire, Ice (both green - Fire and Ice are both Magic-type), dropping the unassigned Ice count to 0, and bumping the Equipped Materia Value to 20 (Fire + Ice are Common, 10 each).

Materia roll odds

Every color has its own jackpot materia (its rarest, most powerful item) at a hand-picked chance; everything else in that color is a fixed fraction of the jackpot's odds based on how good it is: Legendary items (other than the jackpot itself) are 0.9× the jackpot odds, Epic 0.6×, Rare 0.4×, Uncommon 0.2×, Common 0.1× — same formula for every color, only the jackpot number changes. Each roll checks its color's list from rarest to most common against its own independent chance and stops at the first hit; if every single check misses (always possible, even for the most common item), you get that color's most common materia as a guaranteed floor — a roll never comes back empty. Regenerate this table anytime with npm run print-odds.

Red (Summon) works differently. It's a single weighted draw with a linear distribution instead of the independent checks above. Knights of the Round is the chase item at exactly 1 expected per 500 rolls, and every other Summon's expected count per 500 steps up by an equal amount per rarity tier (+30.75 each: Legendary 31.75, Epic 62.5, Rare 93.25, Uncommon 124), so the whole table sums to exactly 500. That's still only an average - any given 500 rolls has about a 63% chance of containing at least one Knights. Knights is also the only Insane-rarity materia, a tier above Legendary.

The Value column is each materia's boss-fight value (see "Materia values" below for the upgrade tiers too). Only base-tier materia show up here - an !upgrade-only tier (Fire2, Mug, 4x Cut, ...) is never rolled for directly; see "Upgrading materia" below for how to get those.

Upgrading materia

!upgrade <materia> merges UPGRADE_MATERIA_COST (5, same count for every chain, so it's one easy-to-remember rule) copies of a materia into one copy of its next tier:

!upgrade Fire
Success! Nevdi, you merged your 5 Fire Materia into Fire2!

Not every materia has a next tier - which ones do mirrors the real FF7 spell lists (Fire/Fire2/Fire3 exist in the actual game, Earth2 never did, so Earth stays single-tier here too). The upgrade-only tiers (the right-hand side of each arrow below) are never !rollmateria-able - the only way to get one is to merge into it:

ChainRarity progression
Fire → Fire2 → Fire3Common → Uncommon → Rare
Ice → Ice2 → Ice3Common → Uncommon → Rare
Bolt → Bolt2 → Bolt3Common → Uncommon → Rare
Gravity → Gravity2 → Gravity3Uncommon → Epic → Legendary
Bio → Bio2 → Bio3Uncommon → Epic → Legendary
HP Plus → HP MaxCommon → Epic
MP Plus → MP MaxUncommon → Epic
Luck Plus → Luck MaxUncommon → Epic
Speed Plus → Speed MaxUncommon → Epic
Steal → MugCommon → Rare
Double Cut → 4x CutEpic → Legendary

So getting to Fire3 takes 5 Fire → Fire2, then 5 more Fire2 → Fire3 (25 base Fire rolled in total); Gravity3/Bio3 end up Legendary-rarity for Materia Power and boss-fight combat value, same as Ultima or Bahamut, even though you can't roll for them directly. Steal upgrading into Mug and Double Cut into 4x Cut are one-step chains (no further tier). Earth, Comet, Ultima, and every "Master" materia (Master Magic, Master Command) have no upgradesTo at all - !upgradeing one of those just tells you so.

Salvaging materia

!salvage <materia> breaks down one spare copy of a materia for XP, for clearing out duplicates you don't need. You get 1/3 of its XP value, rounded down. A materia's XP value is what its color costs to roll:

ColorRoll costSalvage returns
Purple10 XP3 XP
Yellow30 XP10 XP
Green40 XP13 XP
Red100 XP33 XP

So !salvage Ifrit (Red) returns 33 XP. An upgrade-only tier (Fire2, HP Max, Mug, ...) is worth 5× the tier it's merged from - since that's what it took to make - so Fire2 returns 66 XP and Fire3 returns 333. Only copies that aren't in a loadout slot can be salvaged; it never un-equips anything (!unequip first if you want to break down an equipped one). One copy per command.

How equipping works

Materia aren't consumed when equipped — same as the actual game, they're just slotted in. Each slot holds one materia; if you own 3x Fire, you can equip Fire into up to 3 different slots (any more and the bot will tell you you're out).

!equip fills the next open slot automatically — you don't pick a slot number, the bot does, in equipment order (weapon first, then bangle — see "Boss drops" below for how the bangle slot count can grow). You can equip several at once by separating names with commas:

!equip Fire, Ice, Knights of the Round

Each name is processed left to right, so this fills up to three empty slots in one command. If a name isn't something you currently have a spare copy of, you'll get back:

Error - You don't have that materia to equip.

Equipping multiple items in one command and only one fails still equips the rest — the reply lists each item's outcome. If your loadout is already full, !unequip <slot|materia> frees a slot first.

Equipping feeds the "Equipped Materia Value" on !materia as well as boss fights directly — see below.

Pets

Chocobo Lure (Purple, Rare) isn't just a stat stick: while it's equipped, every time you receive XP from watching, you get a hidden 1-in-5000 roll at a Baby Chocobo pet. There's no sign of the roll in chat unless it hits, at which point the bot announces <user> feels like they're being followed. Received Baby Chocobo!. You can only own one, so once you have it the rolls stop. It shows up at the end of your !materia screen as Pet: Baby Chocobo - Ultra Rare. (Only passive watch-time XP counts - an admin !give xp doesn't roll.) At the default 1 XP per minute that's about 5000 minutes (~83 hours) of watching with the Lure equipped, on average.

Boss fights

!fight <boss> uses whatever materia you currently have equipped (not your full collection) to battle one of 8 FF7 bosses. Each materia contributes a fixed value based on its rarity (a few materia, like the numbered upgrades, set their own - see "Materia values" below):

RarityCombat value
Common10
Uncommon20
Rare35
Epic55
Legendary80
Insane120

Add up the value of everything in your equipped slots (3 to start with — see "Boss drops" below for how that grows) to get your "Materia value" for the fight. Your win chance is:

win chance = min(100%, your Materia value ÷ the boss's difficulty)

So 3 equipped Common materia (a fresh, fully-slotted loadout) = 30 value. Against Guard Scorpion's difficulty of 60 — the easiest boss, and a reasonable first fight — that's a 50% chance, and 3 Uncommon materia (3 × 20 = 60) is a guaranteed win. At the other end, 5 Legendary materia (5 × 80 = 400) is a guaranteed win against Motor Ball, the hardest boss. (Knights of the Round, the Insane materia, is worth even more than that.) Everything in between is scaled to match:

(The percentages assume every slot you'd have at that point holds that rarity of materia - "Slots expected" is how many that is: 3 to start, 4 after Aps drops Titan Bangle, 5 after Sample H0512 drops Carbon Bangle.)

A fully-maxed loadout of the right tier wins every fight, but showing up a slot short doesn't: 3 Legendary slots into Reno is ~87%, 4 into Gunner ~94%, and 4 into Motor Ball 80%. So the gear drops still matter for a sure thing - they're just not a wall. Motor Ball's own drop, Mythril Saber, can never help you beat Motor Ball itself (you only get it by beating it), so Motor Ball's 400 is calibrated against the 5-slot cap, not 6. Regenerate the current numbers in chat any time with !materiagame info.

Bosses must be beaten in order, easiest to hardest, in the order listed in the table above. You start at Guard Scorpion; beating a boss moves you up to the next one. Trying !fight on a boss further along than the one you're up to just gets a warning - you must defeat the bosses in order, you're up to <boss> - and doesn't use up your attempt for the window. Bosses you've already beaten can still be replayed (useful for a drop you missed).

Winning pays XP. Beating a boss for the first time pays XP equal to its difficulty; every win after that pays a tenth, rounded down. Losses pay nothing.

Boss drops

Beating certain bosses drops a piece of gear that replaces your current one in the same category (weapon or bangle) and automatically grows your loadout — no separate command, it just happens the moment you win:

BossDropsCategoryMateria slots
ApsTitan Banglebangle2 (up from Iron Bangle's 1)
Sample H0512Carbon Banglebangle3 (up from Titan Bangle's 2)
Motor BallMythril Saberweapon3 (up from Buster Sword's 2)

So a fresh viewer starts at 3 total slots (Buster Sword's 2 + Iron Bangle's 1), goes to 4 after beating Aps, 5 after beating Sample H0512, and - independently, since it's the weapon category rather than another bangle tier - 6 after also beating Motor Ball (3 + 3). Whatever was already equipped carries over automatically when a category upgrades; upgrading never un-equips you, it only adds empty slots to fill - even when a WEAPON upgrade shifts where the bangle category's slots start (Mythril Saber's 3rd slot pushes the bangle category one slot later), the bot migrates your existing equipped materia to the right new slot rather than losing track of it. A drop never downgrades you either: if you've already got Carbon Bangle and re-beat Aps (which only drops the weaker Titan Bangle), nothing changes, and the bot tells you so instead of silently doing nothing - same for re-beating Motor Ball once you already have Mythril Saber.

The other 5 bosses (Guard Scorpion, Air Buster, Reno, Gunner, Rufus) don't have a drop registered yet — winning those is still recorded (so nothing's lost once more rewards are designed) but the bot just congratulates you. Equipment ownership is tracked per user in the database either way; there's no separate command to see it — !materia always shows your current equip screen, slot count included.

A poster-style reference image (commands + each boss with its !fight command) is included for pinning/sharing with chat — see materia-game-boss-guide.png (regenerate with python3 scripts/make-boss-poster.py if the roster or commands change; needs Pillow: pip install pillow). !materiagame replies with the hosted copy's link (GUIDE_IMAGE_URL in .env); re-upload the PNG there after regenerating it.

Leaderboard (!rank)

!rank ranks the top 5 viewers by bosses defeated first — the count of distinct bosses they've beaten at least once (0 to 8), not total win count, so re-beating a boss you've already cleared doesn't pad your ranking. "Materia Power" (total owned materia, weighted by rarity - the same score shown in !materia) is only a tiebreak, used to order two viewers who've beaten the same number of bosses.

This means boss kills always outrank materia collecting: someone who's beaten 3 bosses ranks above someone who's beaten 2, even if the 2-boss viewer has a much bigger or higher-rarity materia collection. Progress through the fight roster is the point of the leaderboard; a deep collection only breaks ties among equally-progressed viewers.

Unlocking !fight (channel points & bits)

!fight is normally locked for everyone. Chat opens it for a limited time by redeeming a channel-point reward or cheering bits - either one opens the exact same window, for every viewer, not just whoever redeemed/cheered - and each viewer only gets one !fight attempt per window, win or lose, no matter which boss they pick:

  • Channel points: redeeming "Unlock Boss Fight" (cost set by FIGHT_UNLOCK_POINT_COST, default 10000) opens !fight for FIGHT_UNLOCK_MINUTES (default 5).
  • Bits: a single cheer of FIGHT_UNLOCK_BITS_THRESHOLD bits or more (default 500) does the same thing - no redemption needed, tmi.js sees the cheer directly in chat.

You don't need to create the channel-point reward yourself - the bot creates "Unlock Boss Fight" on your channel automatically the first time it starts (as long as it has the right scope and your channel supports Channel Points - see Requirements below), and updates its cost on future startups if you change FIGHT_UNLOCK_POINT_COST. Nothing to set up on the Twitch dashboard.

Redemptions/cheers stack: unlocking again while a window is already open adds more time on top rather than resetting the clock, so a run of redeems during a raid or hype train keeps extending it - this is also the only thing that extends a window; a viewer using their one !fight attempt has no effect on the timer either way. !materiagame info shows whether !fight is currently unlocked and, if so, how many seconds are left; if it's locked, it shows the point cost and bits threshold needed to open it. As the broadcaster, you can also open (or extend) the window yourself with !unlockfight [minutes] (see Admin commands below) - handy for testing or a shoutout, without needing an actual redemption; it stacks the same way a real redemption/cheer would.

Requirements and graceful degradation: the channel-points half needs your channel to be Twitch Affiliate or Partner (channel points aren't available otherwise) and the channel:manage:redemptions OAuth scope (see Setup step 5 - if you set this bot up before this feature existed, you'll need to re-run npm run get-token once to pick up the new scope). If either of those isn't in place, the bot logs a warning on startup and simply skips the channel-points half - bits-based unlocking, and the !unlockfight admin override, both keep working regardless. Nothing about this feature can crash or block the rest of the bot; it either sets itself up or quietly stays off.

Want a sound, alert, or OBS effect on redemption? That's a job for Streamer.bot, not this bot. Because "Unlock Boss Fight" is a real Twitch custom reward (created via the Channel Points API, same as one made by hand), it shows up in Streamer.bot's own reward list automatically - Streamer.bot has its own separate connection to Twitch, so it can react to the same redemption this bot reacts to with zero conflict. Add a Twitch → Reward Redemption trigger in Streamer.bot, filter it to "Unlock Boss Fight," and attach whatever sub-actions you want (Play Sound, an alert, an OBS scene change, etc.) - this bot doesn't need to know about any of it. One thing to keep in mind: this bot re-syncs the reward's cost and prompt text to your .env values on every startup, so if you ever want to change those from the dashboard or Streamer.bot instead and have it stick, let it be known - right now the bot is the source of truth for those two fields.

The website

The site/ folder is a small static website - Overview, Readme (this file, rendered) and Hiscores tabs - that can be hosted for free.

  • npm run build-site regenerates the pages from this README and the catalogs (so odds, costs and boss XP on the site can't drift from the bot). Run it after editing the README or the catalogs.
  • The bot writes the current standings to site/hiscores.json every HISCORES_MINUTES (default 10) while it's running; the Hiscores tab reads that file. npm run export-hiscores does it once on demand. Blank HISCORES_PATH turns it off.
  • site/assets/style.css and site/assets/hiscores.js are hand-written - edit them to change the look. site/hiscores.json ships with sample data (flagged on the page) until the bot replaces it.

Publishing the website

Hosting on GitHub Pages (free):

  1. Make a free account at github.com. Your username becomes your address, so pick it with that in mind: a repository named exactly <username>.github.io is served at https://<username>.github.io; any other repository name (say materia-game) is served at https://<username>.github.io/materia-game.
  2. Create that repository (public, empty - no README), then in a terminal: `` cd site git init -b main git add -A git commit -m "Website" git remote add origin https://github.com/<username>/<repository>.git git push -u origin main ``
  1. In the repository on GitHub: Settings -> Pages -> Build and deployment, set Source to "Deploy from a branch", branch main, folder / (root), and save. After a minute or two the site is live at the address above.
  2. To update it later, run npm run publish-site (exports the standings, rebuilds the pages, commits and pushes site/). To have the bot do it itself whenever the standings change, set HISCORES_AUTO_PUSH=true in .env. Git must be able to push without asking for a password: sign in once with GitHub's "Git Credential Manager" (included with Git for Windows) or set up an SSH key.

A custom domain such as nevdismateriagame.com isn't free (roughly $10-15 a year from a registrar like Cloudflare or Namecheap), but it can be pointed at the same GitHub Pages site later under Settings -> Pages -> Custom domain.

Admin commands

These only work when you (the broadcaster - whoever's login matches TWITCH_CHANNEL) type them; anyone else gets a "streamer-only" reply.

CommandWhat it does
!remove <materia name> <user>Removes all copies of that materia from one user (also unequips it)
!removeall <materia name>Removes that materia from every user at once
!give xp <user> <amount>Adds (or, with a negative number, removes) XP
!give materia <user> <materia name> [quantity]Grants materia (default quantity 1)
!give weapon <user> <equipment name>Grants ownership of an equipment item
!unlockfight [minutes]Manually opens !fight for everyone (defaults to FIGHT_UNLOCK_MINUTES if no number given); stacks with any active window the same way a redemption/cheer does

Examples:

!remove Knights of the Round nevdi
!removeall Master Magic
!give xp shyguy42 500
!give materia shyguy42 Ultima 2
!give weapon shyguy42 Iron Bangle
!unlockfight 15

Materia/equipment names accept the same partial matching as !equip (e.g. !give materia shyguy42 ultima works without the exact case/spelling).

Wiping everyone's materia at once

!removeall only targets one materia at a time. For a full reset - e.g. clearing out materia people picked up while idling in chat before XP and rolling existed - there's a terminal script instead of a chat command, on purpose: a full wipe isn't something you want a typo in chat to trigger.

npm run reset-materia            # dry run - shows what it would remove
npm run reset-materia -- --yes   # actually clears it

It empties every user's materia collection and equipped loadout. XP, owned equipment (Buster Sword/Iron Bangle, and anything else granted since), and boss-fight records are left untouched - it's a reset of collections, not of progress.

Setup

1. Create a Twitch application

  1. Go to the Twitch Developer Console and click Register Your Application.
  2. Name it anything, set the OAuth Redirect URL to http://localhost:3000/callback (or whatever you put in TWITCH_REDIRECT_URI), and category to "Chat Bot".
  3. Copy the Client ID, then generate and copy a Client Secret.

2. Pick which account the bot chats as

You've got two options here:

  • Your own main/streaming account. Simplest — no extra account, no modding step (you're the broadcaster, so you're automatically allowed to call Get Chatters on your own channel). The tradeoff: every command reply posts as you, so it'll look like you're replying to yourself in chat rather than a separate bot personality.
  • A dedicated bot account (e.g. materiabot). Keeps replies visually separate from you in chat. Requires one extra step: mod the bot account in your channel's chat, /mod materiabot — required because Get Chatters only works for the broadcaster or a moderator of the channel.

Either way works with everything below — just set TWITCH_BOT_USERNAME to whichever account you pick (your own login, or the dedicated bot's) in the next step, and skip the /mod step if it's your own account.

3. Configure the project

cp .env.example .env

Fill in .env:

  • TWITCH_CLIENT_ID / TWITCH_CLIENT_SECRET — from step 1
  • TWITCH_BOT_USERNAME — the account that will chat (your own login, or a dedicated bot's — see step 2)
  • TWITCH_CHANNEL — the channel to watch, without the #
  • Leave the rest as defaults to start, including the three FIGHT_UNLOCK_* settings that control the channel-points/bits !fight unlock (see "Unlocking !fight" above) - they're pre-filled with reasonable defaults

4. Install dependencies

npm install

(This project wasn't able to npm install inside the sandbox this was built in — no registry access there — so this step needs to run wherever you actually run the bot. All files have been syntax-checked but not yet run against a live install; flag anything that comes up.)

Windows troubleshooting: if npm install fails with a wall of gyp ERR! text ending in "You need to install the latest version of Visual Studio" / "Could not find any Visual Studio installation to use", that's better-sqlite3 trying to compile from source because it couldn't find a ready-made binary for your Node version. As of better-sqlite3 12.1.0+ this should only happen on very new Node releases that don't have a prebuilt binary yet. If it still happens:

  • Easiest fix: install an LTS version of Node (e.g. 20 or 22) instead of a brand-new major version — LTS versions have the widest prebuilt-binary coverage. Check your version with node -v.
  • Otherwise: install "Build Tools for Visual Studio" with the "Desktop development with C++" workload (nodejs.org/en/download/current has the details), then re-run npm install.
  • If a first attempt fails partway through, delete the node_modules folder before retrying — a half-finished install can leave files that block the next attempt.

5. Authorize the account

npm run get-token

This prints a Twitch authorization URL. Open it while logged into the browser as whichever account you set as TWITCH_BOT_USERNAME (your own account, or the dedicated bot account) and approve it. The script starts a tiny local server to catch the redirect, exchanges it for tokens, and saves them to .tokens.json (already git-ignored). It refreshes itself automatically after that — you shouldn't need to run this again unless you revoke access or the bot starts requiring a new scope (the channel-point !fight unlock added channel:manage:redemptions) — if .tokens.json predates that feature, re-run npm run get-token once to re-authorize with the new scope, otherwise the bot just logs a warning and skips the channel-points half of the unlock feature (see "Unlocking !fight" above).

6. Run the bot

npm start

You should see it connect to chat. If your stream is live, viewers should start earning XP after the first tick (a minute by default) - check with !xp, then try !rollmateria purple once you've got at least 10.

Ideas for next iterations

  • !battle <user> - the placeholder command exists (it just replies "coming soon" for now); the planned mechanic mirrors !fight's unlock: redeeming a "Battle" channel-point reward (10000 points) or cheering 501+ bits opens a 5-minute window where everyone can !battle <user> once, the challenged user responds with !accept or !decline, and a win/loss is decided the same way !fight decides boss outcomes (equipped Materia value on both sides).
  • Boss drops exist now for Aps (Titan Bangle), Sample H0512 (Carbon Bangle), and Motor Ball (Mythril Saber) - see "Boss drops" above. The other 5 bosses (Guard Scorpion, Air Buster, Reno, Gunner, Rufus) still have no drop registered. Note that Mythril Saber can never help beat Motor Ball itself (you only get it by beating Motor Ball first, and there's no 9th boss to use it against yet) - so right now it's a completionist trophy, not a progression tool. A 9th boss, or moving a future weapon tier to drop earlier (off Rufus, say), would be the way to actually make a 6-slot loadout usable for something.
  • Reward stats beyond slot count - right now a dropped weapon/bangle only adds materia slots; giving gear its own flat stat bonus (on top of whatever materia end up equipped in it) would make the drops matter even before all the new slots are filled.
  • Trading materia between viewers
  • A bonus XP rate for subs/follows
  • A web dashboard/overlay showing top collectors, or live odds
  • A pity system (guaranteed jackpot after N unlucky rolls of that color)
